# UX audit: E585 Rostering

Date: 27 October 2026. Scope: every member and organiser screen, walked on `next start` with a local Postgres and sample data (names like "Grace Sample", "Sample Song One" are samples, not real members). Each screen was screenshotted with Playwright at 375×812 (phone) and 1280×800 (laptop), as a member, as the owner and signed out. Empty states (no meetings, no songs), error states (wrong PIN, a save that fails), keyboard focus order and reduced motion were checked too.

Guidance used: PRODUCT.md (phone-first, 44px touch targets, WCAG AA, reduced motion), the surface brief `.impeccable/surfaces/src-app.md`, the impeccable audit and craft-floor references, and the emil-design-eng motion and interaction rules.

## What already works well

- The next Friday comes first: the greeting names your role ("Grace, you're on Worship this Friday."), and the window shows open slots with a one-tap **Take it**.
- Taps are optimistic everywhere (take, drop, availability, songs, calendar). A failed save rolls back and shows a toast: "That didn't save. Check your connection and try again."
- Dropping a role already asks first ("Free this slot?" / "Yes, I can't make it").
- Error messages name the problem and the recovery ("That PIN doesn't match. Forgot it? Ask an admin to reset it.").
- No horizontal scroll on any screen at 375px or 1280px. Focus rings are visible, and the tab order follows the page.
- Reduced motion drops movement (press scale, toast slide) and keeps opacity changes.

## What was implemented (DO NOW)

1. **Touch targets of 44px or more** (#1, #8). Small buttons keep their 36px look, and an invisible `::after` extends the tap area to 44px. Segmented choices are 38px with the control's padding included in the tap area (44px). Roster grid pickers, the top-bar avatar link, the brand link, roster column links, section-head links and calendar or Me row links all reach 44px. File: `src/app/globals.css`. Re-measured with `targets.cjs`: no button, link, select or choice under 44px on any screen. The only remaining hits are checkboxes on Roles, which sit inside 44px-tall labels that take the tap.
2. **Send in WhatsApp, plus the phone's share sheet** (#2). The new `ShareButtons` in `src/components/client.tsx` holds a `wa.me` link with the text filled in, which works on phones and desktop. An "Other apps" button opens the native share sheet (Telegram, Messages and so on) only where the browser supports it. It sits next to **Copy roster** on More and on Roster grid, and next to the "can anyone cover?" message on a meeting.
3. **Add to Home Screen as a proper app** (#3). The per-link manifest `src/app/g/[token]/manifest.webmanifest/route.ts` starts at the group's own link, and unknown links get a 404. The group layout adds `<link rel="manifest">` and the Apple web-app meta tags (title is the group name). New icons: `src/app/apple-icon.png` (180px) and `public/icon-192.png`, `public/icon-512.png`, `public/icon-maskable-512.png`, all drawn from the same four-pane mark as `icon.svg`.
4. **Add my serving dates to my calendar** (#4). The route handler `src/app/g/[token]/serving.ics/route.ts` returns an iCalendar file of the Fridays you're confirmed on, with role names and a link to each meeting. Event ids stay the same, so adding it again updates the events instead of duplicating them. It uses only Web APIs and existing data functions, so it runs on Node and on Workers. Signed-out visitors go to "Who are you?". On Me, the **Add my serving dates to my calendar** link appears when you have an upcoming role.
5. **Me: role preferences readable on phones** (#5). The new `.row.pick` class lets the choice wrap under the role name on narrow screens.
6. **Me: show the usual answer** (#6). The text now reads "Not marked, using your usual (Free)".
7. **More: copy fix** (#7). It now reads "The next 3 meetings as plain text…", "The next meeting as plain text…", or "No meetings are planned yet, so for now this is just the link."

No database schema change, no new npm dependency, and no change to sign-in, PIN, lockout, owner or admin rules.
